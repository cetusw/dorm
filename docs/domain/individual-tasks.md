# Индивидуальные задания

Индивидуальное задание — одноразовая самостоятельная задача, назначенная жителю. Оно не связано с `TaskDefinition`, `DutyTask` или дежурством. При создании сохраняется `dormitory_id` текущего общежития исполнителя; последующий переезд жителя его не меняет.

## Состояния

`ISSUED → COMPLETED → VERIFIED`; из `COMPLETED` руководитель может вернуть задачу в `ISSUED`. `VERIFIED` терминально. Повторные complete, reject и verify целевого состояния идемпотентны. Удаление soft-delete допустимо для `ISSUED` и `COMPLETED`.

## Погашение предупреждений

У задания есть `redemption_weight >= 0` с точностью до одного знака. Непроверенные, неудалённые задания резервируют вес: `penalty_balance >= reserved_individual_task_weight`. При подтверждении задания с положительным весом в той же транзакции создаётся `penalty_entry RESOLVE`; собственный резерв задания при этом потребляется. Вес ноль не меняет историю предупреждений.

Операции с предупреждениями, уменьшающие баланс, также проверяют этот резерв. Все изменения баланса или резерва сериализуются блокировкой строки `user`.

## Права и даты

Житель читает и завершает свои задания независимо от текущего общежития. Глава общежития и глава любой группы этого общежития управляют задачами по историческому `task.dormitory_id`. Deadline — необязательная дата: прошлые даты нельзя назначить, но просроченное задание всё ещё можно выполнить и проверить. `is_overdue` — вычисляемое read-model поле только для `ISSUED`.

`version` является optimistic-lock token для редактирования; state-changing операции повторно читают строку `individual_task FOR UPDATE`.
