# Предупреждения (`Penalty`)

## Терминология

В UI используется слово «Предупреждение». В backend и БД сущность называется `Penalty`.

## Назначение

Предупреждение фиксирует нарушение или проблему по жителю:

- кому выдано;
- с каким весом;
- за что;
- на какую дату;
- закрыто оно или ещё активно.

## Модель

Поля:

- `user_id`
- `weight`
- `reason`
- `issued_on`
- `created_at`
- `resolved_at`

Состояния:

- активное: `resolved_at IS NULL`
- разрешённое: `resolved_at IS NOT NULL`

## Инварианты

- `weight >= 0.1`
- `weight` округляется до одного знака после запятой;
- `reason` обязателен и ограничен 256 символами;
- `issued_on` не может быть в будущем относительно app timezone.

## Права доступа

### Глава общежития

Видит и управляет предупреждениями жителей своего общежития.

Scope строится по `dormitory.leader_id`.

### Глава группы

Если пользователь не глава общежития, сервис пытается выдать scope главы группы:

- находит все группы его текущего общежития;
- выбирает группы, где `group.leader_id == currentUser.id`;
- даёт доступ только к жителям команд этих групп.

### Кто не может

- обычный житель;
- глава команды без лидерства группы;
- пользователь без `dormitory_id`.

## Правила выдачи

Создание предупреждения:

1. проверить scope текущего пользователя;
2. убедиться, что целевой житель находится в доступном scope;
3. распарсить `issued_on` в timezone приложения;
4. нормализовать `reason` и `weight`;
5. сохранить запись.

Удаление предупреждения физически не реализовано. `DELETE /api/v1/penalties/:id` означает именно resolve.

## Правила закрытия

`ResolvePenalty`:

- проверяет scope и существование;
- если предупреждение уже закрыто, завершает сценарий без ошибки;
- иначе ставит `resolved_at = now`.

## Суммарный вес и threshold

В query layer считается суммарный активный вес предупреждений по жителю.

Текущий UI-флаг:

- `threshold_reached = total_weight >= 6`

Это используется только как read-model индикатор. Отдельной автоматической санкции в backend нет.
