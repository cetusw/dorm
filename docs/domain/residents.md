# Жители

## Назначение

`User` описывает жителя, который может:

- входить в resident web-приложение;
- состоять в команде;
- быть главой команды, группы или общежития;
- получать предупреждения и уведомления.

## Идентичность

Поля идентичности:

- `id`
- `login`
- `password_hash`
- `first_name`
- `middle_name`
- `last_name`
- `created_at`

Аутентификация — логин/пароль с Argon2id и независимыми серверными сессиями устройств. Полное описание cookie, ограничений входа и отзыва — в [авторизации](../architecture/authorization.md). Внешнего auth-provider нет.

## Организационная принадлежность

Текущая принадлежность хранится отдельно от идентичности:

- `dormitory_id`
- `team_id`
- `floor_number`
- `room_number`

Группа выводится косвенно через текущую команду: `user.team_id -> team.group_id`.

## Полномочия

Полномочия не хранятся отдельным enum.

Они выводятся из:

- `dormitory.leader_id`
- `group.leader_id`
- `team.leader_id`
- `user.team_id`

Смена этих связей немедленно меняет права пользователя.

## Soft delete

Удаление жителя — soft delete через `user.deleted_at`.

Следствия:

- пользователь исчезает из обычных выборок и логина; все его сессии отзываются в той же транзакции, middleware запрещает дальнейший доступ;
- предупреждения, уведомления и история дежурств остаются в БД;
- push subscriptions и notifications каскадно очищаются только если запись пользователя была бы удалена физически, чего текущий код не делает.

## Изменение команды

Смена команды делается через `MoveUserToTeam`.

Влияние:

- resident task permissions сразу переключаются на новую команду;
- пользователь может потерять доступ к старому active duty, если больше не состоит в его команде;
- история прошлых дежурств не закрепляет его старую роль как snapshot.

## Login contract

Проверки `user.Service`:

- логин обязателен;
- допустимые символы: `[a-z0-9._-]`;
- пароль обязателен при создании и обновлении: минимум 6 латинских букв/цифр;
- имя/фамилия и необязательное отчество — до 255 символов кириллицы, пробелы и дефис; логин — до 255 символов;
- общежитие обязательно и должно существовать; этаж — от −1000 до 1000, 0 представлен как отсутствие этажа; комната — необязательный текст до 255 символов;
- для UI bootstrap первый пользователь создаётся отдельным shell script.

Имена жителей в CRUD:

- backend ожидает кириллицу в имени и фамилии;
- frontend использует собственные формы и валидацию поверх API.

## Где реализовано

- домен: `pkg/core/domain/user/user.go`
- auth и current user: `pkg/core/usecase/user/service.go`
- HTTP: `pkg/adapters/http/resident_auth.go`, `user.go`
- persistence: `pkg/infrastructure/mysql/repository/user.go`

## Изменение credentials и конкурентность

`Create` использует INSERT, изменение — UPDATE по ID активной записи. Уникальный индекс запрещает одинаковые логины активных пользователей; удалённая запись не восстанавливается при сохранении.

При обновлении требуется пароль. Если он соответствует текущему Argon2id, изменяются только профильные поля. Иначе новый Argon2id и отзыв всех сессий сохраняются в транзакции с блокировкой пользователя и проверкой ожидаемого старого хеша. Конкурентно изменившиеся credentials приводят к ошибке, а обычное редактирование не перезаписывает пароль.

## Расхождение ограничения комнаты

Валидация CRUD допускает room_number до 255 символов, но итоговая SQL-схема содержит VARCHAR(50). До согласованного исправления реализации используйте не более 50 символов; более длинное прошедшее валидацию значение может быть отклонено MySQL. Документация не расширяет фактическую колонку.
