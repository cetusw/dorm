# Команды и группы

## Назначение

- `Dormitory` — верхний уровень организации.
- `Group` — единица дежурств внутри общежития.
- `Team` — ротационная команда внутри группы.

## `Group`

Поля:

- `id`
- `leader_id`
- `name`
- `dormitory_id`

Группа:

- объединяет команды;
- владеет историей `Duty`;
- определяет scope duty settings;
- определяет scope доступа главы группы.

## `Team`

Поля:

- `id`
- `name`
- `group_id`
- `leader_id`
- `color`
- `rotation_position`

`rotation_position` нормализуется в домене: значение `<= 0` заменяется на `1`.

## Ротация

Актуальный механизм:

- хранится в `team.rotation_position`;
- уникален в пределах группы;
- используется для выбора следующей дежурной команды;
- может быть изменён через duty settings reorder.

Старая модель через `team_order` и `group.next_duty_team` уже неактуальна и удалена миграциями.

## Membership

Членство задаётся текущим `user.team_id`.

Следствия:

- пользователь может быть только в одной команде одновременно;
- смена команды мгновенно меняет его resident permissions;
- история прошлых дежурств не хранит snapshot состава команды.

## Глава команды

`team.leader_id`:

- может быть `NULL`;
- должен указывать на пользователя, который уже состоит в этой команде;
- используется для review задач и для отображения history/current-duty.

Единственного главу команды удалить нельзя. Если в команде есть другие участники,
текущего главу можно исключить только вместе с указанием другого действующего
участника как replacement leader. Замена лидера и исключение выполняются одной
транзакцией: частичное изменение состава недопустимо.

## Изменение состава

Через duty settings доступны операции:

- добавить участника в команду;
- снять участника;
- назначить главу команды;
- создать/обновить/удалить команду.

Ограничения:

- участник должен принадлежать тому же общежитию;
- если участник уже в другой команде той же группы, его можно перевести;
- если участник лидер своей текущей команды, перевод блокируется, пока не назначат другого лидера;
- участник из другой группы трактуется как недоступный.
- replacement leader при исключении главы уже должен состоять в этой же команде;
  его нельзя выбрать из другой команды или добавить этой операцией.

## Переназначение active duty team

В duty settings можно вручную переназначить текущую активную неделю на другую команду той же группы.

Последствия:

- меняется `duty.team_id`;
- `duty.group_id` пересчитывается по новой команде;
- все `duty_task` этого дежурства сбрасывают assignment/completion/verification.

Это не создаёт новое `Duty`, а мутирует активное.

## Изменение порядка

`UpdateRotationPositions` делает транзакционный reorder:

1. временно сдвигает все `rotation_position` внутри группы на `+N`;
2. выставляет новый порядок `1..N`.

Это позволяет обойти unique-конфликт по `(group_id, rotation_position)` во время перестановки.

## Влияние текущего состава на дежурства

- выбор следующей команды идёт по текущему составу таблицы `team`;
- действия жителя с задачами зависят от текущего `user.team_id`, а не от исторического состава на момент старта duty;
- history leader name тоже берётся из текущего `team.leader_id`.
