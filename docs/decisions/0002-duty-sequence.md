# ADR-0002: Duty sequence и sequence-based recurrence

## Статус

Accepted

## Контекст

Периодичность задач не должна зависеть от фактической даты выполнения:

- задачу могут завершить позже календарной недели;
- ручные переносы и задержки не должны ломать расписание;
- история дежурств нуждается в явном стабильном порядке.

Ранняя модель через `task.frequency` по дням была для этого хрупкой.

## Решение

Ввести:

- `duty.sequence_number` — порядковый номер дежурства внутри группы;
- `task.recurrence_interval` — шаг повторения по sequence;
- `task.start_sequence` — номер первого дежурства, с которого задача активна.

Включение задачи определяется формулой:

`(duty.sequence_number - task.start_sequence) % recurrence_interval == 0`

при `recurrence_interval > 0` и `sequence_number >= start_sequence`.

## Последствия

- появляется явная и стабильная последовательность duty внутри группы;
- recurrence больше не зависит от фактической даты выполнения;
- `sequence_number` должен быть уникален внутри группы;
- ordering истории больше не выводится косвенно из календаря;
- override-механизм остаётся поверх recurrence и может одноразово включить или исключить задачу.
