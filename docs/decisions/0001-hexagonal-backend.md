# ADR-0001: Hexagonal backend

## Статус

Accepted

## Контекст

Сервис одновременно решает доменные задачи дежурств, HTTP API, cron-сценарии, уведомления и persistence в MySQL. Без разделения слоёв доменная логика быстро смешивается с Fiber handler-ами и SQL.

## Решение

Использовать разделение на:

- `domain`
- `ports`
- `usecase`
- `adapters`
- `infrastructure`

Business core не зависит от Fiber и MySQL напрямую. Внешние интеграции подключаются через интерфейсы из `ports` и DI-контейнер.

## Последствия

Плюсы:

- проще тестировать бизнес-сценарии без HTTP и БД;
- scheduler и HTTP используют один и тот же use-case слой;
- можно добавлять новые адаптеры без протекания transport-логики в домен.

Издержки:

- больше интерфейсов и DTO;
- часть read-model приходится реализовывать отдельными query service;
- требуется дисциплина, чтобы не тащить SQL и transport-правила обратно в use-case.
